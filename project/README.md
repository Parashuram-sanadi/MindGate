# 📱 Electronic Gadget Addiction Prediction & Digital Wellness Intervention System

A complete, production-ready machine learning system that predicts student gadget
addiction risk (**Low / Moderate / High / Severe**) from survey data, explains its
predictions with SHAP, applies a clinical **danger-gate validation** layer for
Severe-risk classifications, serves predictions via a **FastAPI** backend, and
provides personalised digital wellness recommendations — with full **Android
(Kotlin/Retrofit)** integration support.

## 🚀 Quick Start

### 1. Installation

```bash
cd project
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Training

Run the full pipeline (EDA → preprocessing → SMOTE → CV → Optuna tuning →
model selection → SHAP):

```bash
python main.py train
# or
python train.py
```

This generates:
- All plots in `plots/`
- All reports in `reports/`
- Trained artifacts in `models/`

> ⏱ Full training (incl. Optuna tuning of 4 models) takes ~5–8 minutes on a
> standard CPU.

### 3. Evaluation

```bash
python main.py evaluate
# or
python evaluate.py
```

Generates `reports/classification_report.txt`, confusion matrix, and ROC curves
for the selected best model.

### 4. CLI Prediction

```bash
python predict.py --screen_time "9+" --sleep_hours 4.0 --stress_level 5 \
                   --phone_checks "10+" --late_night "Always"
```

### 5. API Server

```bash
python main.py serve
# or
uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload
```

Open API docs at **http://localhost:8000/docs**

### 6. Running Tests

```bash
python -m pytest tests/ -v
```

## 🎯 Risk Classification Framework

| Risk Level | Score Range |
|------------|-------------|
| Low        | 0 – 34      |
| Moderate   | 35 – 54     |
| High       | 55 – 64     |
| Severe     | ≥ 65 *(with danger-gate validation)* |

### Danger Gate Validation (Severe Risk)

A predicted **Severe** risk is only confirmed if **all three** of the following
hold:

1. `gate1_score_valid` — risk score threshold met
2. `gate2_danger_met` — sufficient danger markers present
3. `gate3_loss_control` — explicit loss-of-control reported

If any gate fails, the prediction is **automatically downgraded to High**.
This logic lives in [`risk_engine.py`](risk_engine.py) and is fully unit-tested
in [`tests/test_risk_engine.py`](tests/test_risk_engine.py).

## 🔒 Data Leakage Prevention

The following columns are **derived from the target** and are **excluded from
training** (see [`reports/leakage_report.md`](reports/leakage_report.md)):

```
Predicted_AddictionRisk, computed_risk_score, score_usage_compulsion,
score_sleep_physical, score_academic_impairment, score_emotional_dependence,
score_social_withdrawal, score_loss_of_control, danger_marker_count,
gate1_score_valid, gate2_danger_met, gate3_loss_control, all_gates_pass
```

These are retained **only** for post-processing / danger-gate validation, never
as model inputs.

## 🌐 API Usage

### `POST /predict`

**Minimal request:**
```json
{
  "screen_time": "7-9",
  "sleep_hours": 5.0,
  "stress_level": 4,
  "phone_checks": "10+"
}
```

**Response:**
```json
{
  "risk_level": "High",
  "risk_score": 60,
  "confidence": 0.87,
  "recommendation": "Schedule specific gadget-free hours each day (at least 3 hours).",
  "recommendations": ["...", "...", "..."],
  "intervention_level": "Intervention",
  "timestamp": "2026-06-13T12:00:00Z",
  "model_version": "1.0.0"
}
```

### Other Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/health` | Health check + model info |
| POST | `/predict` | Single prediction |
| POST | `/predict/batch` | Batch prediction (max 100) |
| GET | `/risk-levels` | Risk band definitions |
| GET | `/recommendations/{level}` | Recommendations for a risk level |

Valid input bands:
- `screen_time`: `<2`, `2-3`, `3-5`, `5-7`, `7-9`, `9+`
- `phone_checks`: `1-2`, `3-5`, `6-10`, `10+`
- `stress_level`: integer 1–5

Optional fields enrich predictions (year of study, gender, sleep quality,
emotional coping, etc.) — see [`api/schemas.py`](api/schemas.py).

Missing fields are automatically filled using **dataset-derived defaults**
and **correlated-field derivation** (see
[`src/feature_derivation.py`](src/feature_derivation.py)) so the API works
correctly with just the 4 core fields.

## 🩺 Recommendation Engine

[`recommendation_engine.py`](recommendation_engine.py) provides tiered
recommendations:

- **Low** → Positive reinforcement, habit maintenance tips
- **Moderate** → Healthy usage suggestions, screen time goals
- **High** → Intervention suggestions, counsellor referral
- **Severe** → Strong intervention, app restriction, professional help, helplines

Plus dynamic **factor-specific tips** based on sleep, stress, screen time, and
phone-checking frequency.

## 🧰 Troubleshooting

| Issue | Solution |
|-------|----------|
| `ModuleNotFoundError` | Run `pip install -r requirements.txt` |
| `FileNotFoundError: best_model.pkl` | Run `python train.py` first |
| CatBoost `subsample` error | Ensure `bootstrap_type="Bernoulli"` is set (already handled) |
| 422 on `/predict` | Check `screen_time`/`phone_checks` are valid band strings, `stress_level` is 1–5 |
| Android emulator can't reach API | Use `10.0.2.2:8000` instead of `localhost:8000` |
| SMOTE fails on tiny minority class | `k_neighbors` is capped at 3 (already handled) |
| Optuna runtime too long | Reduce `OPTUNA_TRIALS` in `configs/config.py` |
