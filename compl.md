# MindGate: Technical Documentation & System Overview

MindGate is a sophisticated digital-wellbeing ecosystem that addresses electronic gadget addiction using Artificial Intelligence. The system provides a multi-role collaborative environment for Students, Parents, and Teachers to monitor, assess, and regulate digital habits.

---

## 📂 Project Folder Structure

### 📱 Android Application (`mindgate-android/`)
The application is built using **Jetpack Compose** and follows **Clean Architecture** with the **MVVM** pattern.

*   **`app/src/main/java/com/mindgate/`**
    *   **`data/`**: The data source layer.
        *   `local/`: Room Database (DAOs & Entities) and DataStore (Session Management).
        *   `remote/`: Retrofit API interfaces, DTOs, and Network Result handlers.
        *   `repository/`: Implementation of repositories (UserRepository, UsageRepository, ParentRepository, FirestoreRepository).
    *   **`domain/`**: The business logic layer.
        *   `manager/`: Core engines like `ExtensionManager` (manages time grants) and `PolicyEngine` (applies risk-based rules).
        *   `model/`: Plain Kotlin data models used throughout the UI.
    *   **`presentation/`**: The UI layer.
        *   `ui/auth/`: Login/Register, Google Auth, and Role Selection.
        *   `ui/home/`: Student Dashboard, usage ring, and global protection toggles.
        *   `ui/parent/`: Parent Dashboard, Child Detail analytics, and Linking handshake.
        *   `ui/teacher/`: Teacher Analytics center for bulk student analysis.
        *   `ui/blocked/`: Dark-themed Focus Overlay and extension request logic.
        *   `ui/quiz/`: Wellness Challenge engine (Math/Trivia) for self-regulation.
        *   `ui/theme/`: Centralized design tokens (AppIcons.kt, Color.kt, Motion.kt).
        *   `navigation/`: NavGraph and RoleGuard logic.
    *   **`parent/`**: Accessibility Service and background watchdog listeners for parents.
    *   **`util/`**: Essential helpers (AssessmentMapper, AppInfo, Logging).

### ⚙️ Backend & AI Intelligence (`project/`)
The brain of the system, powered by **FastAPI** and **CatBoost**.

*   **`api/`**: 
    *   `main.py`: The entry point with 20+ endpoints for auth, linking, and prediction.
    *   `models.py`: SQLAlchemy schemas for the relational database (PostgreSQL/SQLite).
    *   `firebase_utils.py`: Logic for generating Custom Auth Tokens and sending Cloud Messages.
*   **`models/`**: Serialized `best_model.pkl` and `risk_mapping.json`.
*   **`src/`**: Preprocessing pipelines to convert raw survey answers into ML-ready numerical vectors.
*   **`reports/`**: Documentation of model performance (F1-score: 0.9758).
*   **`mindgate_backend.db`**: SQLite instance storing persistent user data and usage history.

## 🚀 System Functionalities

### 1. AI Risk Analysis (Risk Engine)
*   **Data Collection**: A comprehensive 38-feature survey assessing physical health, academic impact, and usage patterns.
*   **Classification**: Uses a CatBoost model to categorize users into **Low, Moderate, High, or Severe** risk levels.
*   **Personalization**: Automatically generates a "Wellness Plan" with custom daily limits based on the risk score.

### 2. Intelligent App Blocking (Accessibility Watchdog)
*   **Real-time Monitoring**: Accessibility Service detects the foreground app package name.
*   **Enforcement**: If the package matches a restricted app and the limit is exceeded, it launches the `BlockedOverlayActivity`.
*   **Focus Mode**: The overlay uses a high-impact dark theme to effectively stop addictive behavior.

### 3. Collaborative Time Extensions
*   **Wellness Challenges**: Students solve math or trivia puzzles. Success grants 15 minutes of "Earned" time.
*   **Parental Approval**: Students send requests to parents. Firestore listeners trigger a high-priority notification on the parent's phone.
*   **Manual Override**: Parents can remotely approve time from their dashboard, which dismisses the student's block screen in <500ms.

### 4. Cross-Platform Handshake (Linking)
*   **Mechanism**: A 6-digit alphanumeric code (e.g., MG-6C95A156) is generated by the student.
*   **Backend Sync**: Once the parent enters the code, the backend establishes a permanent relationship in SQL and a real-time data bridge in Firestore.
*   **Security**: Links are protected by Global Security Rules using `studentUid` and `parentUid`.

## 🔄 The "MindGate Identity" (Unique Innovation)
The system uses **Firebase Custom Tokens** to align the SQL database ID with the Firebase UID. 
*   **The Problem**: Standard Firebase Auth assigns random UIDs, making it hard to link to a custom backend database.
*   **The Solution**: MindGate's backend generates a token based on the user's SQL ID (e.g., ID 108). When the app signs in with this token, its Firebase UID becomes "108". This ensures that a Parent listening for "Child 108" is always looking at the correct document path.
